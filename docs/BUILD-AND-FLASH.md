# Build and program

Target: NUCLEO-L476RG / STM32L476RG, Cortex-M4F, hard-float FPv4-SP-D16.
Vendored firmware support files are from STM32Cube FW_L4 V1.18.2.

## STM32CubeIDE

1. Use **File → Import → Existing Projects into Workspace** and select
   `firmware/cubeide/`. The project is named `Cyclodial Actuator`.
2. Build the supplied project with the STM32 GNU toolchain. Do not replace
   `Core/Src/main.c` with the older PlatformIO file. Regenerating the IOC is not
   required to build the vendored source; preserve USER CODE if regenerating.
3. The Debug/Release output is generated by CubeIDE. Generated build folders
   and machine-specific launch/debug state are not included in the source package.

## Optional command-line build, without CubeIDE UI

Use Python 3 and an already installed GNU Arm Embedded toolchain. Nothing is
installed or downloaded by the script:

```sh
python3 tools/build_firmware.py --toolchain-bin /path/to/arm-none-eabi/bin
```

If `arm-none-eabi-gcc`, `arm-none-eabi-objcopy` and `arm-none-eabi-size` are already
on PATH, omit `--toolchain-bin`. The script compiles only, producing ELF, BIN,
HEX, a map and a JSON build report in `build/`. It never connects to a board.

## Included prebuilt image

`releases/usb-panel-3/` contains ELF, BIN and HEX built from this exact source.
The fresh BIN matches the archived working protocol-3 image. See
`docs/OFFLINE-VALIDATION.json` and `SHA256SUMS` for checksums. The ELF contains
flash addresses and is the simplest prebuilt choice for CubeProgrammer.

## Programming with ST-LINK

With the motor supply off and the mechanism supported, connect the Nucleo's
ST-LINK USB connector. In STM32CubeProgrammer select ST-LINK, connect to the
L476RG and program the ELF produced by your build, using verify. The ELF carries
its flash addresses; the supplied flash linker script starts at `0x08000000`.
Alternatively use CubeIDE's Debug/Run download for this imported project.

After reset the firmware starts RELEASED. Close any serial monitor before
opening the browser panel; the debugger may remain open if it is not using serial.
Confirm protocol 3 / `usb-panel-3` before enabling the motor supply for an
operator-controlled test. A successful build does not measure actuator performance.

## Offline checks

```sh
node --test usb-panel/tests/controller.test.js
python3 tests/test_cubeide_usb_control.py
```

These are transport/conversion and host-simulation checks. They do not move hardware.
